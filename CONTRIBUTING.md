# Contributing

Lore is built as a centaur: one human maintainer and a frontier model in a tight plan, build, review loop (see [CLAUDE.md](CLAUDE.md)). Every committed line has a human who can explain it. That constraint shapes how contributions work here.

## Pull requests

The project does not currently accept pull requests. The codebase is small and opinionated, and the "explain every line" rule does not absorb outside patches well. This is not a judgment of your code; it is a property of how Lore is developed. A pull request, however good, will not be merged.

## Issues are the way in

Open an issue for anything:

- bugs and unexpected behavior, with steps to reproduce;
- feature ideas and design arguments;
- questions about the architecture or the epistemics;
- corrections to the docs or the math.

A sharp issue moves the project further than a patch would. Describe the fix you have in mind and the maintainer will carry it in, with credit.

## Security

Do not report vulnerabilities in public issues. Use GitHub's private vulnerability reporting; [SECURITY.md](SECURITY.md) has the process, the response expectations, and the scope.

## Code of Conduct

Participation is governed by the [Code of Conduct](CODE_OF_CONDUCT.md). Taking part means upholding it.
